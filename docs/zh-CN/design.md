# UniSearch 设计概览

[English](../en/design.md) · [README](../../README.zh-CN.md)

UniSearch 位于调用方和检索服务之间，负责选择来源、执行请求并返回结果。搜索的结果按来源分别保留；网页读取和站点发现按配置顺序尝试，直到有一家服务完成操作。

本文说明这些行为及其取舍。字段、默认值和覆盖方式见[配置](configuration.md)，命令参数见各命令的 `--help`。

## 命令与入口

`search`、`fetch` 和 `map` 为同类操作提供统一入口，共享输出、超时等选项。各服务特有的功能由 `unisearch <服务 ID> <操作>` 形式的专用命令提供，例如按发表年份筛选论文用 `unisearch tinyfish search`，批量提取网页用 `unisearch tavily extract`；文档查询的命令见[文档查询](#文档查询)。

## 统一搜索

统一 `search` 以两种方式确定来源：使用固定列表，或按查询自动选择。固定列表来自 `search.providers` 配置，也可由本次调用的 `--sources` 指定，显式指定的列表优先于自动选择。字段默认值、覆盖方式和示例见[统一搜索配置](configuration.md#统一-search)。

使用固定列表时，命令在发出请求前逐项检查：服务须已启用且必需配置齐全，查询也不得超出该服务的已知限制，例如 DeepSeek 的 128 字符上限。任一检查失败，命令报错，不发出任何搜索请求。

来源确定后，UniSearch 向各来源并行发送同一条查询，并按选源顺序分别保留结果。调用方据此比较各来源找到的资料，也能看出哪些来源失败。某个来源失败时，命令不会改用其他服务代替它。

### 自动选源和选参

`search --auto` 把来源和参数拆成两个分类步骤。分类器依据查询与服务能力做判断，选中的服务或模型执行实际检索。

1. **找候选。** 从支持统一搜索的服务中筛选，跳过已禁用、缺少必要设置或查询超出已知限制的服务。候选服务的配置无效时，命令报错，例如地址格式错误。
2. **选来源。** 有多个候选时，UniSearch 把查询和各来源的能力说明发给配置的分类器模型，由它判断各来源与查询的匹配程度；配置上限允许多选时，还会估计需要几家。CLI 将达到 `0.7` 的来源按分数排序，按分类器建议的数量选取，且不超过配置上限；达标来源不足时，实际数量少于建议数量。
3. **选参数。** 已选服务支持自动选参时，UniSearch 另行发起一次分类，把查询和各服务当前可选参数的取值发给分类器，由它在允许的选项中选择，例如通用网页或新闻。已保存的搜索模式、深度和引擎只作为偏好，分类器可以改选。参数只用于本次调用。

只有一个候选时，CLI 直接选用，有参数要选时才调用分类器。没有候选、没有来源达标或分类失败时，命令在发出搜索请求前报错。凭证、开关和数量上限见[自动选择配置](configuration.md#自动选择搜索来源)。

### 模型搜索

模型搜索既能单独运行，也能作为统一 `search` 的一个来源。模型服务执行配置的搜索工具并整理回答，有引用时一并返回。与其他来源并行时，其他来源的结果直接返回调用方，不传给模型。

模型搜索与分类器分别配置。主模型和备用模型共用 API 地址和凭证。当前模型不可用或响应无效时，可按[模型配置](configuration.md#模型配置)中的顺序尝试备用模型。

## 网页读取与站点发现

`fetch` 处理已知的网页地址，按服务返回正文、摘录或页面元数据。`map` 从一个站点内的地址出发，发现站内的其他链接，只返回链接而不含正文。例如先用 `map` 找到文档站的指南地址，再用 `fetch` 读取选中的页面。

两者都只需要一家服务完成操作。命令按 `fetch.providers` 和 `map.providers` 的顺序尝试，跳过已禁用或缺少必要配置的服务，成功后结束。启用切换时，限流、单次请求超时等错误会转由下一家尝试。若服务报告目标网页返回 `401`、`404`、`410` 或 `451`，`fetch` 停止读取，不再切换服务，因为这些状态说明网页本身无法读取。`--no-fallback` 将调用限制在第一个可用服务，仍可按设置重试该服务。候选列表见[统一 fetch 与 map 配置](configuration.md#统一-fetch-与-map)。

## 文档查询

Context7（`unisearch ctx7`）处理库和 API 文档：

- `search`：按问题检索相关库的文档。
- `library`：按库名查找库 ID，供按版本读取文档。
- `docs`：用库 ID 和问题读取文档及示例。
- `fetch`：读取已知的公开文档页，可只提取与问题相关的段落。

智谱 MCP（`unisearch zhipu-mcp`）查询公开代码仓库，仓库以 `owner/repo` 指定：

- `docs`：查询仓库文档。
- `tree`：列出仓库目录。
- `read-file`：读取仓库文件。

## 超时、重试和取消

重试是在同一服务或同一模型上再次尝试。UniSearch 依据错误、重试次数和剩余时间决定是否重试；服务给出有效的 `Retry-After` 时按其等待，否则逐步延长间隔。切换在候选之间进行，只发生在两处：模型搜索换用备用模型，统一 `fetch` 和 `map` 换用列表中的下一家服务。重试次数与切换开关分别设置。

分类、检索、重试等待和切换都计入本次调用的总时限。单次服务请求的时限取总时限与该服务的单次上限中较小者，超时错误用 `error.details.timeout_scope` 标明是单次请求超时还是整次调用到期。用户中断会立即终止进行中的请求，整次调用按取消处理，已取得的数据随结果返回。

流式模型请求的计时规则不同：模型服务须在总时限内返回首段文本；此后每收到新的模型文本即重置计时，超过设定时长没有新文本才算超时，心跳和工具进度不计。因此持续返回文本的请求可以超过最初的总时限，而并行搜索中的其他来源仍受原时限约束。开始返回文本后若回答中断，模型任务报错，不再重试或切换模型。执行参数见[执行设置](configuration.md#执行设置)。

## 结果与输出

`search` 和 `model search` 都按来源返回结果。单来源搜索失败时，命令保留该来源的错误码。多来源搜索按来源报告失败原因，并保留已取得的结果。

| `status`  | 退出码     | 含义                                                         |
| --------- | ---------- | ------------------------------------------------------------ |
| `success` | `0`        | 命令已完成，搜索也可能没有命中。                             |
| `partial` | `6`        | 部分操作失败，结果和错误一起返回。                           |
| `error`   | 其他非零值 | 命令失败。可能仍返回失败前取得的资料，使用前要看错误和警告。 |

`error` 的退出码表示失败类别：`2` 是命令或参数错误，`3` 是配置、认证或权限错误，`4` 是网络、超时、限流、额度或服务端失败，`5` 是本地文件或内部错误，`130` 是用户中断。每条错误的具体原因由 `error.code` 和 `error.message` 说明。

检索命令默认输出 Markdown，`--format json` 输出结构化结果。网页读取会标明返回正文的服务，正文截断、提取不完整等问题会记录在 `warnings` 中。

`--output PATH` 将结果写入文件而不再写到标准输出。成功和有数据的失败都会写入；失败且没有可保存数据，或调用被取消时不写入，原文件保持不变，结果改为输出到标准输出。文件内容同样可能来自部分成功或失败前的资料，仍需检查退出码。发生模型或服务切换时，`meta.model_fallbacks` 或 `meta.service_fallbacks` 记录切换双方与原因。`--verbose` 输出每次尝试的服务或模型、耗时、HTTP 状态、错误码与重试等待。JSON 放在 `meta` 中，Markdown 写到标准错误。
